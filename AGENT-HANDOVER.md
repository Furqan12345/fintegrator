**Tenancy removal (2026-11-20):** Fusetor is sold as a single-deployment, self-hosted platform: one deployment serves one customer. The `ITenantContext`/`TenantContext` layer, `TenantId` columns, EF global query filters, the `tenant_id` JWT claim and the Elasticsearch `tenant_id` field have been removed. `DatabaseSchemaInitializer.RemoveTenancy` runs at startup on both providers; it is idempotent, refuses to run if any table contains more than one distinct `TenantId`, and on SQLite writes `ipaas.db.bak-pre-remove-tenancy-<yyyyMMdd-HHmmss>` before changing anything. SQL Server takes no automatic backup: back it up before deploying this version. `AlertSettings` is now a host-wide single row (`Id = 1`). Existing JWTs that still carry `tenant_id` keep working because the claim is ignored.

**Email node (2026-11-20):** New `StepType.Email` card sends mail through the existing `IEmailSender` / `Email:Smtp` configuration. Config lives in `StepConfig` (`to`, `cc`, `bcc`, `replyTo`, `subject`, `body`, `isHtml`, `useScript`, `continueOnError`). Static To/CC/BCC/Reply-To/Subject/Body text accepts `{{flowState.Node.path}}` and `{{persistedState.path}}` placeholders through `EmailTemplate.Render`; paths support indexes and `[*]` wildcards (joined with “, ”), missing paths become empty and are reported, `\{{` is a literal `{{`, and inserted values are HTML-encoded only in an HTML body. Addresses and the subject reject CR/LF after resolution to prevent header injection. The node sends one `EmailMessage` with real To/CC/BCC/Reply-To headers and a single SMTP call, so a failure means nobody was emailed. With `useScript=true`, `MappingCode` runs through `IAdvancedCodeExecutionService.ExecuteEmailAsync` and returns an object (`{to, cc, bcc, replyTo, subject, body, isHtml}`); returned fields override static values, missing fields fall back, and script output is not re-rendered. Scripts read upstream output with `JObject.Parse(FlowStateJson)["NodeName"]`, not `state["trigger"]`. The node passes its input through unchanged and records `{sentTo, cc, bcc(count), replyTo, subject, sentAt, missingPlaceholders?}` (never the body) as the step response. Flow test runs record the resolved preview including the body without sending; designer Debug runs send. Replay blocks an Email node unless the flow has `AllowPostReplay`; bulk replay reports “Replay would resend an email”. SMTP credentials stay in server config.

- **`store:false` + our own DB history (deliberate).** The Responses strategy always sends `store:false` and re-sends the whole transcript every turn: the app already persists chat sessions, transcripts and job state in its own tables, so OpenAI-side storage would duplicate the history, leak deployment data to a third party, and couple the agent loop to a 30-day server-side retention. Consequence: nothing may rely on `previous_response_id` — the loop translates its chat-shaped messages into Responses `input` items itself (`instructions` from system/developer turns, user → `input_text`, tool → `function_call_output` keyed by `call_id`, assistant tool calls → `function_call`).
- **Azure api-version gating.** Azure keeps `ChatCompletions` by default and only uses Responses when the operator picks it; whether a given api-version/deployment supports it is decided by Azure, and the provider's own error text ("The API version … does not support the Responses API") is surfaced verbatim with the HTTP status by `ProviderErrorMessages` — no client-side guessing.
- **Deferred:** OpenAI's code-interpreter and other built-in tools (only `web_search` is wired); `store:true`/Conversations API (`previous_response_id`) intentionally not adopted for the reason above. No live Responses call was possible in this environment (stubbed `HttpMessageHandler` only; the configured upstream is Azure-hosted and previously returned 402 for that surface) — the live check that did run is a legacy ChatCompletions provider test returning 200.

**Pluggable storage: Elasticsearch for growing datasets (2026-10-17):** logs, packet logs (messages) and cross-reference entries can now live in **SQLite or Elasticsearch**, chosen per dataset on the new `/settings` page (sidebar: System → Storage). Everything that does not grow — flows, integrations, connections, API keys, AI settings, runs/steps and dead letters — stays in SQL; executions are SQL-only on purpose because the Engine claims queued runs and dead letters with atomic conditional updates. Wiring lives in `SimpleIPaaS.Infrastructure/Storage` and `.../Elasticsearch`; both hosts call `AddIPaaSStorage()`. Index design is ILM-friendly: `<prefix>-<dataset>-<period>` (daily `yyyy.MM.dd`, ISO-weekly `yyyy.Www`, monthly `yyyy.MM`), a `<prefix>-<dataset>-write` alias that writers always address, an index template with mappings + `index.lifecycle.name`/`rollover_alias`, and an ILM policy whose delete phase equals the dataset's retention (omitted when retention is 0). Reads, counts, mget and retention all use `<prefix>-<dataset>-*`. `POST /api/storage/apply` creates/repairs the plan idempotently; the settings API also exposes test/status/run-retention. Retention runs in both hosts (`StorageRetentionWorker`, 15 min): ES deletes whole expired indices only when ILM is off for that dataset, otherwise ILM owns deletion; SQL deletes rows in bounded batches and never touches queued/running executions. The app's own settings row (`StorageSettings`, single host-wide row) is read through `IStorageSettingsProvider` (5 s cache, decrypted secrets) and published to hot paths by `StorageRuntime` (background 5 s loop + immediate invalidation after a save) — a dataset switch therefore applies immediately on the host that saved and within ~5 s on the other.

**Cross-reference ids after tenancy removal:** old Elasticsearch cross-reference documents were keyed by tenant + list + key; the current code keys them by list + key, and dedup is a multi-get by id. Old documents are therefore invisible and already-seen keys would count as new. Elasticsearch storage has not shipped; when enabling it on an upgraded deployment, start with an empty cross-reference index (or delete the old `fusetor-cross-references-*` indices and the `fusetor-cross-references-write` alias). Log and packet-log document ids did not change.

The client builds its own handler-free `HttpClient`, and `System.Net.Http.HttpClient` is in `DatabaseLoggerProvider.AlwaysExcludedCategoryPrefixes`. Also fixed during verification: the ES username was never mapped into the snapshot, so Basic auth was silently dropped (now persisted and sent; API keys already worked).

## 2. Running it

dotnet run --project src/SimpleIPaaS.Api    # :5000 — REST, triggers, scheduling

## 3. Traps that will bite you

These are real defects that were found the hard way. Each one failed *silently*.

### Enums are persisted as INTEGER — append only
`StepType` and `ExecutionStatus` in `src/SimpleIPaaS.Domain/Enums.cs` are stored by ordinal. **Inserting a value mid-enum silently corrupts every existing row.** Always append.

### There are TWO StepType enums
`Domain/Enums.cs` **and** a private duplicate inside `src/SimpleIPaaS.Client/Pages/FlowDesigner.razor` (bottom of the file). Adding a node type means editing both.

### Unknown step types silently become `Mapping`
`DtoMappings.ToEntity` does `Enum.TryParse<StepType>(...) ? stepType : StepType.Mapping`. Miss an enum entry and your node quietly turns into a Mapper instead of erroring.

### Every executor branch activates its own outgoing edges
In `FlowExecutor`, each node-type branch runs its own `activeNodes.Add(...)` loop. A node type with **no** branch still executes, produces empty output, and **never activates its downstream edges** — the rest of the flow just silently doesn't run. Always add the branch *and* its activation loop.

### `EnsureCreated()` is a no-op on an existing database
`DatabaseSchemaInitializer` is the **only** migration mechanism — there are no EF migrations.
- New **column** → `EnsureColumn(...)` (must be nullable or have a DEFAULT; SQLite requires it).
- New **table** → an explicit `CREATE TABLE IF NOT EXISTS` helper (see `EnsureCrossReferenceTables`). `EnsureCreated()` will **not** create it on an existing DB.
- Neither backfills existing rows — keep UI fallbacks for old data.

### No EF navigation properties
`IPaaSContext` wires every execution relationship as `HasOne<T>().WithMany()` with no navigation property, so **`Include` is impossible**. To show related data, denormalize it at write time (that's why `FlowExecution` carries `FlowName`/`IntegrationName` and `StepExecution` carries `NodeName`).

### Secrets use an "empty means keep" convention
All APIs redact secrets on read (`AuthConfigJson` etc. come back as `""`). On save, **empty means "keep what's stored"**. If a client blindly rebuilds a config object from redacted (blank) fields and sends it, it will **overwrite real credentials with blanks**. This bug has been introduced twice — once for Connections, once for step-level auth. Both are fixed; don't reintroduce it. UI shows "Stored — leave blank to keep".

### Roslyn only checks its CancellationToken *before* the script starts
`ScriptRunner` never observes the token again once running, so a `while(true)` cannot be cancelled. The services race the script against a wall-clock timeout instead. **Residual limitation:** a runaway script still occupies a thread until the process recycles — only an out-of-process sandbox fixes that (roadmap).

### Changing an interface or `FlowExecutor`'s constructor breaks the tests
`tests/SimpleIPaaS.Tests/TestDoubles/StubRepositories.cs` implements the repository interfaces, and `FlowExecutorDagTests` constructs `FlowExecutor` directly. Update both.

### Blazor: never let an effect throw
An unhandled exception in a Fluxor effect trips Blazor's error boundary and shows a permanent red bar until manual reload. **Use `SafeFetch.GetAsync` / `SafeFetch.SendAsync`** (`Store/SafeFetch.cs`) for all HTTP — they surface a toast instead.

## 5. Design decisions worth respecting

- **Recovery preserves history.** A resynced dead letter marks the step (and, once *all* siblings resolve, the execution) as `Recovered`. The original `ErrorMessage` is deliberately never cleared, and every attempt is appended to `AttemptHistoryJson`. Don't "tidy up" by clearing these — that was the original bug.
- **Cross-reference keys are declarative dotted paths**, not scripts — avoids Roslyn cost and sandbox caveats. The executor has **no loop construct**, so the filter processes a whole array in one pass with **one bulk existence query** per node. Don't make it per-record.
- **Schedule node owns the trigger.** If a Schedule node is on the canvas it is the source of truth; the settings modal shows a read-only summary so the two can't disagree. One-time schedules clear their marker *before* enqueuing (at-most-once) and a past date never resurrects.
- **Cron is always evaluated server-side** (`POST /api/integrationflow/cron-preview`, Cronos). A previous client-side parser silently rejected valid 6-field expressions. Don't reintroduce client-side cron parsing.
- **POST replay is opt-in per flow** (`AllowPostReplay`), because replaying a non-idempotent POST can duplicate its side effect.

## 7. Known limitations (deliberate, documented)

Do not treat these as bugs to fix casually; they are scoped decisions recorded in `architecture/solution-architecture.md` §12 and the presentation's limitations slide.

1. **Single-node deployment.** SQLite + an in-process queue. Scale-out needs PostgreSQL + distributed locks. The repository abstraction makes it a provider swap.
2. **In-process scripting.** Trust model is "authenticated users are trusted script authors." Hostile-author isolation needs an out-of-process sandbox.
3. **No mid-flow wait node.** The engine is one synchronous topological pass with no suspend/resume; a durable-continuation redesign would be required.
4. **HTTP-family connectors only** — no queue/DB/SFTP node types yet.
5. **No response pagination** in HTTP actions (the domain reserves `PaginationStyle` for it).
6. **Cross-reference keys are field paths**, not expressions — no computed/derived keys.
7. **Old rows lack denormalized names** (schema upgrades don't backfill); UI falls back to truncated GUIDs.
8. **Cosmetic:** new nodes spawn under the designer toolbar and need dragging clear.
